# Проверка проекта

Проверено 3 октября 2026 года после перевода интеграции на WhatsApp.

| Проверка               | Результат                                                                       |
| ---------------------- | ------------------------------------------------------------------------------- |
| `npm test`             | 25 тестов, 2 файла, все проходят                                                |
| `npm run build`        | TypeScript и production-сборка Vite проходят                                    |
| `npm audit --omit=dev` | 0 известных уязвимостей в runtime-зависимостях                                  |
| Браузер, 1280 × 720    | Подключение, инструкция, демочат, отправка по Enter и ответ                     |
| Браузер, 390 × 844     | Мобильная переписка, возврат к списку, поиск, новый чат с номером +1            |
| Браузер, 320 × 568     | Форма прокручивается; ширина документа 320 px, горизонтального переполнения нет |

Production-предпросмотр проверен в браузере. Ошибок и предупреждений в консоли не обнаружено. Скриншоты обновлены для WhatsApp; они показывают деморежим с локальными вымышленными данными.

Дополнительно исправлена ошибка вызова нативного fetch: транспорт вызывался как метод GreenApi с недопустимым для браузера receiver. До исправления браузер воспроизводил `Illegal invocation`, который ошибочно отображался как отсутствие связи. Регрессионный тест воспроизводит эту проверку receiver. В production-сборке контрольный запрос к GREEN-API с заведомо неверным тестовым токеном теперь получает ожидаемый HTTP 401 и показывает ошибку авторизации. Реальные токены для этой контрольной проверки не использовались.

Контракт сверён с официальной документацией GREEN-API: [CheckWhatsapp](https://green-api.com/docs/api/service/CheckWhatsapp/), [SendMessage](https://green-api.com/docs/api/sending/SendMessage/), [особенности адресов lid](https://green-api.com/docs/faq/lid-important-differences/). Приложение проверяет номер методом checkWhatsapp с параметром chatId, использует возвращённый адрес @lid или совместимый @c.us для прежних ответов API. Формат URL: `/waInstance<id>/<method>/<token>`.

Автоматические тесты используют тестовый HTTP-транспорт: подключение, настройки, CheckWhatsapp, SendMessage, ReceiveNotification и DeleteNotification. Проверены международные номера, сохранение явного кода +81, адреса @lid и @c.us, сопоставление ответа по номеру с созданным lid-чатом, дедупликация и сохранение до подтверждения уведомления. Группы и рассылки пропускаются даже при отсутствии chatType в уведомлении.

Проверены ошибка запроса, явный повтор отправки, сохранение черновика при отказе localStorage, независимость отправки от перезапуска получения, статус noAccount, ограничения инстанса suspended и сохранение статуса read при запоздалых уведомлениях. Исходящее API-уведомление, пришедшее до HTTP-ответа отправки по другому формату адреса, не создаёт второй пузырь сообщения.

Полный сценарий проверяет отдельный ключ истории WhatsApp и сохранность прежних ключей MAX и Telegram. Токен не записывается в localStorage. Ошибка доставки без idMessage подтверждается и показывается общим предупреждением, без попытки присвоить её одному из нескольких сообщений.

**Реальная переписка WhatsApp проверена пользователем 3 октября 2026 года.** Пользователь авторизовал и настроил личный инстанс, подключился из локального приложения, создал чат по номеру телефона и подтвердил, что отправленное сообщение дошло до получателя. Затем пользователь подтвердил появление ответа получателя в приложении. Это подтверждает основной сценарий отправки и получения на его инстансе; результат записан со слов пользователя, без независимого наблюдения переписки агентом. Токен пользователь вводил самостоятельно, в документацию он не включён. Проверка публичного размещения ещё не проводилась.
