# WhatsApp Chat — React + GREEN-API

Тестовое задание на позицию «Фронтенд разработчик React». Минимальный интерфейс для отправки и получения текстовых сообщений в WhatsApp через GREEN-API. В задании разрешён вариант для WhatsApp вместо MAX. Компоновка сохраняет прототип веб-чата MAX: список слева, переписка справа. Это самостоятельный интерфейс, а не официальный клиент.

Экран подключения и переписка используют одну оболочку мессенджера. Графитовая палитра, плоские поверхности и синий акцент выделяют сообщения и активный чат. На узком экране список чатов и переписка открываются по отдельности; при маленькой высоте окна форма подключения прокручивается целиком.

## Локальный запуск

Нужен **Node.js 22.12+** и npm. Из папки проекта:

```bash
npm ci
npm run dev
```

Откройте адрес, который выведет Vite, обычно **http://127.0.0.1:5173**. Если порт занят, Vite выберет следующий свободный.

Не открывайте `index.html` двойным кликом: проект запускается через Vite.

Для проверки интерфейса без аккаунта нажмите **«Открыть демочат»**. В этом режиме используются вымышленные контакты, ответы генерируются локально, запросы в GREEN-API отсутствуют. После выхода демоистория сбрасывается.

## Подготовка GREEN-API для WhatsApp

1. Войдите в существующий аккаунт WhatsApp на телефоне. Для проверки понадобится другой пользователь WhatsApp — получатель сообщений. Подходит обычный WhatsApp или WhatsApp Business.
2. Зарегистрируйтесь в [личном кабинете GREEN-API](https://console.green-api.com/).
3. Нажмите **«Создать инстанс»** и выберите **WhatsApp: Developer**. Бесплатный тариф ограничивает число чатов; для проверки достаточно одного получателя. Актуальные условия: [тарифы GREEN-API](https://green-api.com/docs/about-tariffs/). Используйте отдельный инстанс WhatsApp: данные Telegram и MAX не подходят.
4. В карточке инстанса нажмите **«Получить QR»**. На телефоне откройте WhatsApp → **Связанные устройства → Привязка устройства**. На iPhone этот раздел находится в настройках, на Android — в меню с тремя точками. Отсканируйте QR-код и дождитесь состояния **`authorized`**. Секреты в переписку и репозиторий не отправляйте.
5. В настройках инстанса **оставьте `webhookUrl` пустым**. Включите:
   - уведомления о входящих сообщениях и файлах — `incomingWebhook: "yes"`;
   - сообщения, отправленные с телефона — `outgoingMessageWebhook: "yes"`;
   - сообщения, отправленные через API — `outgoingAPIMessageWebhook: "yes"`;
   - статусы исходящих сообщений — `outgoingWebhook: "yes"`.
6. Сохраните настройки. Применение может занять время; после изменения повторите подключение.
7. Скопируйте из карточки инстанса **`idInstance`**, **`apiTokenInstance`**, **`apiUrl`** и введите их на странице приложения. Например, apiUrl имеет вид `https://1103.api.green-api.com`, но использовать нужно адрес именно вашего инстанса.

Приложение проверяет авторизацию и настройки входящих уведомлений. Оно не изменяет настройки инстанса автоматически. Если исходящие уведомления отключены, сообщение может оставаться со статусом «В очереди GREEN-API», даже если получатель уже получил его.

Официальные источники:

- [Подготовка и авторизация инстанса](https://green-api.com/docs/before-start/)
- [Получение через HTTP API и настройка уведомлений](https://green-api.com/docs/api/receiving/technology-http-api/)
- [Отправка текста SendMessage](https://green-api.com/docs/api/sending/SendMessage/)
- [Проверка номера CheckWhatsapp](https://green-api.com/docs/api/service/CheckWhatsapp/)
- [Статусы исходящих сообщений](https://green-api.com/docs/api/receiving/notifications-format/outgoing-message/OutgoingMessageStatus/)

## Проверка реальной переписки

1. Подключитесь к подготовленному инстансу.
2. Нажмите **+** и введите номер получателя в международном формате, например `+7 999 123-45-67`. Поддерживается код страны и 7–15 цифр. Пробелы, скобки и дефисы допускаются; начальная `8` для 11-значного номера без `+` преобразуется в `7`. Приложение проверит наличие WhatsApp на номере.
3. Приложение вызовет **CheckWhatsapp** с адресом `<номер>@c.us` и сохранит возвращённый **chatId** (обычно `<ID>@lid`). Для прежних ответов API без chatId используется `<номер>@c.us`. Ответы и исходящие уведомления по `@c.us` сопоставляются с сохранённым `@lid` по номеру телефона, чтобы не создавать вторую переписку. Идентификатор `@lid` не формируется самостоятельно.
4. Напишите текст и нажмите **Enter** или кнопку со стрелкой. **Shift + Enter** добавляет новую строку. Максимум — 4000 символов.
5. Убедитесь, что текст появился у получателя в WhatsApp. Успех SendMessage означает принятие в очередь GREEN-API; доставку и прочтение подтверждают отдельные уведомления.
6. Ответьте с аккаунта получателя. Ответ должен появиться в том же чате браузера. В других чатах появится счётчик непрочитанных.
7. Перезагрузите страницу: потребуется снова ввести данные доступа. После подключения выберите сохранённый чат — локальная история восстановится.

Тестировать инстанс нужно **в одной вкладке**. Не запускайте параллельно другой клиент, который потребляет ту же очередь ReceiveNotification. Входящие уведомления подтверждаются DeleteNotification и удаляются из очереди GREEN-API. Сообщения неподдерживаемых типов и групповые сообщения подтверждаются и пропускаются; их содержимое остаётся доступным в самом WhatsApp.

Редкая смена `@lid` сервисом не переносит прежнюю переписку автоматически. Приложение не загружает все контакты и не изменяет настройку `enableLidMode`; детали форматов описаны в [официальной документации](https://green-api.com/docs/faq/lid-important-differences/).

## Что реализовано

- Ввод данных инстанса, скрытие/показ токена, проверка авторизации и настроек.
- Создание личного чата по номеру через CheckWhatsapp с поддержкой адресов @lid и @c.us.
- Отправка текста методом `sendMessage`.
- Последовательный цикл `receiveNotification → обработка и сохранение → deleteNotification`.
- Отображение входящего текста, текста со ссылкой, исходящих текстовых уведомлений и статусов.
- Повторное получение уведомления не создаёт дубликаты. Исходящие API-уведомления сопоставляются с локальным сообщением.
- Ошибка доставки WhatsApp без idMessage показывается общим уведомлением: приложение не пытается угадать, к какому исходящему сообщению она относится.
- Ошибки запроса видны пользователю. После ошибки получения применяется пауза с увеличением до 30 секунд. HTTP 401/403 останавливают цикл до ручного возобновления или нового входа.
- Неудачная отправка сохраняется в переписке; повтор возможен по кнопке. Автоматического повторения отправки нет: при сетевой ошибке сервер мог уже принять сообщение. Перед повтором проверьте WhatsApp, чтобы не отправить дубликат.
- Поиск по имени/номеру, переключение чатов, непрочитанные, адаптация под мобильный экран.
- Явно обозначенный деморежим и встроенная инструкция подключения.

## Архитектура

| Файл                    | Назначение                                                               |
| ----------------------- | ------------------------------------------------------------------------ |
| `src/api.ts`            | Валидация, GREEN-API методы, таймауты и отмена запросов                  |
| `src/polling.ts`        | Последовательное получение и подтверждение уведомлений, обработка ошибок |
| `src/store.ts`          | Чаты, локальная история, дедупликация, сопоставление исходящих сообщений |
| `src/App.tsx`           | Экран подключения, создание сессии                                       |
| `src/ChatWorkspace.tsx` | Список чатов, переписка, новый чат и отправка                            |
| `src/components.tsx`    | Общие элементы и инструкция                                              |
| `src/demo.ts`           | Изолированный демонстрационный транспорт                                 |
| `src/styles.css`        | Тёмный интерфейс и адаптивная компоновка                                 |

React подписывается на ChatStore через `useSyncExternalStore`. История записывается синхронно до подтверждения уведомления: если запись не удалась, DeleteNotification не вызывается. Polling работает один раз на сессию и отменяется при выходе. Перезапуск получения не отменяет текущую отправку.

Использованы React, TypeScript, Vite, обычный CSS и Lucide React для иконок. Бэкенд для тестового задания не требуется: запросы выполняются из браузера к HTTPS API GREEN-API.

## Хранение и ограничения

Токен хранится только в памяти вкладки. Он не попадает в localStorage, URL страницы или исходники. По контракту GREEN-API токен присутствует в URL API-запроса и доступен в Network браузера; это ожидаемая особенность прямой клиентской интеграции. В реальном многопользовательском продукте доступ к API следует вынести на сервер.

Чаты и сообщения сохраняются в localStorage с ключом `whatsapp-chat:v1:<apiUrl>:<idInstance>`. Истории прежних версий MAX и Telegram не читаются и не изменяются; их можно открыть, вернувшись к соответствующему коммиту Git. Выход сохраняет историю; очистка данных сайта удаляет её. Неподтверждённая отправка после перезагрузки помечается как неудачная. История хранится без шифрования и не синхронизируется между браузерами. Полная прежняя история из WhatsApp не загружается; приложение отображает собственные отправки и полученные через очередь уведомления.

Деморежим использует только оперативную память. В проекте нет реальных токенов или контактов. React выводит текст как текст, без интерпретации HTML.

При CORS-ошибке проверьте правильность apiUrl и поддержку запросов из браузера у сервиса. Не отключайте защиту браузера. Серверный прокси можно добавить отдельно, если этого потребует окружение размещения.

## Сборка и тесты

```bash
npm test
npm run build
npm run preview
```

Автоматические тесты проверяют контракт API, разрешение номера, дедупликацию, сохранение до подтверждения, отмену, ошибки, сохранение текста и полный пользовательский сценарий с тестовым HTTP-транспортом.

Реальная отправка и приём WhatsApp требуют личного авторизованного инстанса. Проверки на тестовом транспорте и деморежим не заменяют проверку из раздела «Проверка реальной переписки».

## Размещение

После `npm run build` папку `dist` можно разместить на статическом хостинге с HTTPS. Команда сборки: `npm run build`, выходная папка: `dist`. Секретные переменные окружения для фронтенда не нужны: пользователь вводит свои данные в интерфейсе. Для GitHub Pages с вложенным путём настройте `base` в Vite под адрес репозитория.
